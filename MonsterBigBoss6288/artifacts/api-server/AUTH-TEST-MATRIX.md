# مصفوفة التحقق اليدوي لمصادقة لوحة التحكم

تُنفّذ هذه الاختبارات في بيئة staging معزولة بعد تهيئة متغيرات المصادقة. لا تستخدم جلسة Facebook حقيقية، ولا تختبر الكتابة إلى مخزن الإنتاج. لا تستدعِ مسار `/testsend` بمصادقة صحيحة على بوت حقيقي لأنه يرسل رسالة؛ اختبر حدّ عدم المصادقة فقط أو استخدم `botApi` بديلاً في بيئة اختبار.

| الحالة | الإجراء | النتيجة المتوقعة |
|---|---|---|
| الإعداد ناقص | ابدأ الخدمة دون `DASHBOARD_PASSWORD` أو `DASHBOARD_SESSION_SECRET` ثم اطلب حالة الجلسة ومسارات التحكم | يبلّغ `/api/auth/session` أن المصادقة غير مهيأة؛ ترفض مسارات التحكم برسالة 503؛ لا تظهر اللوحة |
| دخول صحيح | اضبط كلمة مرور اختبارية لا تقل عن 16 محرفاً ومفتاح جلسة عشوائياً لا يقل عن 32 بايت؛ سجّل الدخول من أصل اللوحة | 200، ويصدر Cookie باسم `__Host-alth_admin_session` مع `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/`؛ لا تظهر كلمة المرور في URL أو السجلات |
| دخول خاطئ / تحديد محاولات | من أي عنوان، أرسل 20 محاولة خلال أي فترة متحركة مدتها 15 دقيقة ثم محاولة إضافية؛ كرر باستخدام قيم متنوعة أو مزورة لـ`X-Forwarded-For` | المحاولات العشرون الأولى فقط تصل لفحص كلمة المرور؛ التالية ترد 429 مع `Retry-After` حتى انتهاء أقدم محاولة من النافذة. لا يوجد حظر منفصل حسب IP ولا يلزم `TRUST_PROXY_HOPS` |
| تزوير Origin | أرسل login/logout أو طلب تغيير من Origin مخالف، أو `Origin: null` | 403؛ لا تُنشأ جلسة ولا يحدث تغيير |
| حماية المسارات المحمية | بلا Cookie صالح اطلب `/api/bot/status`, `/api/bot/admins`, `/api/bot/commands` وPOST/DELETE الخاص بها، و`/bot/cookies`, `/reconnect`, `/updatecookies`, `/testsend` على خادم البوت | 401 أو 503 قبل تنفيذ أي عملية؛ `/api/healthz` و`/ping` عامّان ولا يعرضان بيانات تحكم (`/ping` على خادم البوت) |
| مسارات المصادقة العامة | بلا جلسة اطلب `GET /api/auth/session` ثم جرّب `POST /api/auth/login` و`POST /api/auth/logout` من أصل اللوحة في `production` دون ضبط `TRUST_PROXY_HOPS` | الثلاثة لا تتطلب جلسة سابقة عمدًا: `session` يعيد فقط `configured` و`authenticated` مع `no-store` ولا يتطلب Origin؛ `login` يتطلب Origin مسموحًا، وإعداد مصادقة صالحًا وكلمة المرور، ويطبق الحد العام؛ غياب `TRUST_PROXY_HOPS` لا يعطل login؛ `logout` يتطلب Origin مسموحًا ويمسح Cookie حتى دون جلسة سابقة. أصل مخالف يعطي 403 لـ login/logout |
| انتهاء/تلاعب/خروج | اختبر Cookie معدلًا أو منتهيًا، ثم logout ثم كرر طلباً محمياً | 401؛ يمسح logout Cookie بنفس السمات ويمنع إعادة الاستخدام |
| عميل الواجهة المولد | بعد الدخول افتح اللوحة وتأكد أن طلبات `/api/` تنجح بالجلسة؛ اختبر أيضاً أصلًا خارجياً وملفًا ثابتاً غير API | طلبات `/api/` من أصل الصفحة تستخدم `credentials: same-origin` حتى لو طلبها عميل مولد بخيار `omit`; لا تُضاف بيانات اعتماد لطلبات أصل آخر أو لملفات ثابتة |
| ترويسات العميل الواردة | جرّب `X-Forwarded-For` مختلفة أو مزورة من عميل مباشر وخلف الوكيل؛ تحقق من إعداد Express | `trust proxy` يظل `false`، ولا يقرأ مسار الدخول `req.ip` أو `X-Forwarded-For`؛ جميع الطلبات تتشارك المحدد العالمي للعملية. ترويسات التمرير لا تغيّر الحد ولا تمنحه حصصًا منفصلة |
| مصدر جلسة Railway | عيّن `APPSTATE_JSON` إلى مصفوفة JSON اصطناعية غير قابلة لتسجيل الدخول، ثم ابدأ البوت؛ لا تستخدم جلسة حقيقية لهذا الاختبار | تُقبل فقط مصفوفة غير فارغة من كائنات الجلسة؛ يفشل التحميل برسالة عامة عند JSON غير صالح أو نوع/مصفوفة فارغة، من دون طباعة القيمة أو قراءتها من ملف؛ لا تُكتب الجلسة إلى القرص |
| تحديث الجلسة في Railway/الإنتاج | بعد مصادقة صحيحة، أرسل POST إلى `/api/bot/cookies` أو `/updatecookies` | `409 Conflict` برسالة تطلب تغيير `APPSTATE_JSON` في Railway وإعادة النشر؛ لا يحدث أي استدعاء كتابة لملف الجلسة |
| بديل التطوير المحلي | في بيئة `development` فقط، اضبط `APPSTATE_PATH` على ملف JSON اصطناعي خارج المستودع واتبع مسار التحديث المحلي | يستخدم الملف المحلي فقط عند غياب `APPSTATE_JSON`؛ لا يُقبل `APPSTATE_PATH` في Railway/الإنتاج، ولا تُستخدم بيانات جلسة حقيقية في هذا الاختبار |

## حدود واختبارات متاحة

محدد الدخول نافذة متحركة محدودة الذاكرة تعمل داخل **عملية Node واحدة فقط**: 20 محاولة إجمالية لكل 15 دقيقة، بلا حد حسب IP أو مفاتيح لكل عميل. إعادة التشغيل تصفّر العداد، وتعدد Railway replicas لا يشارك العدادات؛ لذلك يمكن مضاعفة الحد مع كل replica. أبقِ الخدمة ذات نسخة واحدة ما دام هذا المحدد المحلي مستخدمًا. لا يقرأ مسار الدخول `req.ip` أو `X-Forwarded-For`، و`TRUST_PROXY_HOPS` غير مطلوب ومتجاهل.

Express مضبوط صراحةً على `trust proxy = false`. لا يعتمد Cookie الجلسة على `req.secure`؛ يُضاف علم `Secure` صراحةً، إضافةً إلى `HttpOnly`, `SameSite=Strict`, و`Path=/`. هذا يضمن أن المتصفح يرسل Cookie عبر HTTPS فقط من دون الحاجة إلى ترويسات الوكيل. تحقق من السلوك عبر HTTPS في staging قبل النشر؛ الاختبارات الاصطناعية المحلية لا تتحقق من ingress الفعلي.

تختبر وحدة الأمان محليًا الحد المتحرك وانتهاء المحاولات الاصطناعية. وتختبر حزمة API ربط المسار بالحد العام، عدم وجود حاجز `TRUST_PROXY_HOPS` في production، وغياب أي مدخل من ترويسات IP الممررة. هذه اختبارات مصدر/وحدات اصطناعية وليست اختبار Express تكامليًا أو تحققًا من Railway. أوامر التشغيل من جذر المشروع:

```sh
node --test MonsterBigBoss6288/bot/security.test.cjs
node --test MonsterBigBoss6288/artifacts/api-server/src/routes/auth.test.mjs
node --test MonsterBigBoss6288/artifacts/control-panel/src/same-origin-fetch.test.mjs
```
